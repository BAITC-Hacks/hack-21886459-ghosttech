# GhostTech

Платформа для подготовки бизнес-задач, оценки их готовности и работы с откликами команд.
**Backend:** Python + FastAPI + SQLAlchemy + SQLite. **Frontend:** HTML + CSS + JavaScript без сборки.

Текущая версия локальная и работает **без авторизации**. Задачи, команды, отклики и подтверждение этапов доступны всем, кто имеет доступ к серверу. Сервер разработки слушает `127.0.0.1`.

## Быстрый запуск

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/). Из корня репозитория:

```sh
make setup
make seed
make dev
```

- Сайт: http://127.0.0.1:8000/
- Swagger: http://127.0.0.1:8000/docs
- OpenAPI: http://127.0.0.1:8000/openapi.json
- Проверка сервера: http://127.0.0.1:8000/api/health

`make setup` устанавливает зависимости из `backend/uv.lock`, создаёт `backend/.venv`, копирует `.env.example`, если `.env` отсутствует, и применяет миграции. `make seed` загружает примеры без дубликатов и без перезаписи ваших изменений. Остановка сервера: Ctrl+C.

Без `make`:

```sh
uv sync --project backend --locked
uv run --directory backend --locked python -m app.cli setup
uv run --directory backend --locked python -m app.cli seed
uv run --project backend --locked uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Можно оставить фронтенд на отдельном сервере:

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory frontend
```

При открытии сайта на `8080` клиент обращается к FastAPI на `8000` с тем же именем хоста. Для другого адреса задайте `window.API_BASE_URL` до подключения `api.js`. Список разрешённых адресов браузера задаётся через `FRONTEND_ORIGINS`.

## Структура

```text
backend/
  app/
    main.py          # Точка входа
    api.py           # Создание FastAPI, CORS, раздача HTML/CSS/JS
    config.py        # Переменные окружения и backend/.env
    database.py      # SQLAlchemy engine и сессия на запрос
    models.py        # Task, Team, Proposal, Progress
    schemas.py       # Pydantic-контракты запросов и ответов
    routes.py        # API задач, команд, откликов и прогресса
    scoring.py       # Расчёт рейтинга
    assistant.py     # Демо-анализ черновика и сборка карточки
    seed.py          # Загрузка sample_data без перезаписи
    cli.py           # Настройка, миграции, seed, экспорт OpenAPI
  migrations/        # Миграции Alembic
  data/              # SQLite; исключена из Git
  tests/             # Тесты API и БД
frontend/
  index.html
  styles.css
  app.js             # Интерфейс и асинхронные запросы
  api.js             # fetch-клиент к FastAPI
  mock.js            # Старый демо-источник; больше не подключён к странице
  tests/             # Проверки API-клиента без браузера
sample_data/         # Исходные примеры задач, команд, откликов
prompts/             # Контракты помощника и подсказки по полям
```

## База данных и миграции

По умолчанию база — `backend/data/app.sqlite3`. Относительные SQLite-пути в `DATABASE_URL` считаются от `backend/`, поэтому запуск из другого каталога не создаёт случайную вторую базу.

`backend/.env` читается автоматически. Переменные окружения имеют приоритет:

```dotenv
DATABASE_URL=
FRONTEND_ORIGINS=["http://127.0.0.1:8080","http://localhost:8080"]
```

После изменения моделей создайте и проверьте миграцию:

```sh
uv run --directory backend --locked alembic revision --autogenerate -m "describe schema change"
make migrate
uv run --directory backend --locked alembic check
```

Перед обновлением рабочей базы сохраните её копию. Приложение не изменяет схему автоматически при старте. Историческая миграция `0001` содержала аккаунты; `0002` удаляет их и связи владельцев, сохраняя задачи, команды и отклики. Обратное восстановление удалённых аккаунтов возможно из резервной копии, автоматический downgrade `0002` не предусмотрен. Таблица старых демо-заметок сохраняется, но `/api/notes` больше не используется.

Для PostgreSQL предусмотрен драйвер:

```sh
uv sync --project backend --extra postgres --locked
```

```dotenv
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/ghosttech
```

Затем примените миграции к созданной PostgreSQL-базе. Перенос существующих данных из SQLite выполняется отдельно; в этой работе тестировалась SQLite.

## Основной сценарий

1. В мастере нажмите «Подставить пример», затем «Проанализировать».
2. Ответьте на вопросы и нажмите «Собрать карточку».
3. Заполните поля. Рейтинг и подсказки рассчитывает API.
4. Перейдите к публикации, подтвердите сведения и опубликуйте задачу.
5. В каталоге нажмите «Откликнуться», выберите команду, заполните идею, план и срок.
6. В разделе «Бизнес: отклики» выберите задачу и примите отклик.
7. Подтвердите этапы: прототип, тестирование, финал. Баллы начисляются по одному разу.
8. Перезапустите сервер — опубликованная задача, решение и баллы сохранятся.

Кнопка «Команды» создаёт или редактирует команду. Кнопка «Редактировать карточку» в разделе откликов открывает сохранённую задачу в мастере.

## API

Полный контракт, примеры типов и схемы доступны в `/docs`. Также см. [backend/API.md](backend/API.md).

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/health` | Проверка соединения с БД |
| POST | `/api/tasks/analyze` | Уточняющие вопросы |
| POST | `/api/tasks/build-card` | Карточка из черновика и ответов |
| POST | `/api/tasks/score` | Рейтинг, расшифровка и подсказки |
| GET | `/api/tasks` | Опубликованные задачи; фильтры, сортировка, пагинация |
| GET | `/api/tasks/{id}` | Карточка с откликами |
| POST | `/api/tasks` | Создать задачу или неопубликованную карточку |
| PATCH | `/api/tasks/{id}` | Обновить карточку или подтверждение публикации |
| GET / POST | `/api/teams` | Список / создание команды |
| PATCH | `/api/teams/{id}` | Изменить команду |
| GET / POST | `/api/tasks/{id}/proposals` | Список / создание отклика |
| PATCH | `/api/proposals/{id}/decision` | Принять или отклонить |
| POST | `/api/proposals/{id}/progress` | Подтвердить этап |

## Рейтинг и правила

Максимальные баллы: контекст 10, потребность 10, данные 20, результат 15, критерии успеха 15, ограничения 10, участники 10, контакт 5, формат взаимодействия 5.

Уровни: `draft` — 0–39, `working` — 40–69, `ready` — 70–89, `priority` — 90–100. Формула полноты перенесена из исходного `mock.js`; подсказки учитывают также частично заполненные поля. При загрузке sample_data рейтинг пересчитывается из карточек — исторические числа в JSON могут отличаться от результата формулы.

Рейтинг всегда считает сервер. Неопубликованные карточки исключены из каталога по умолчанию; `include_drafts=true` включает их. `confirmed` — факт публикации, `level` — качество заполнения, это независимые признаки.

Одна команда может отправить один отклик на задачу. Решение меняется только из `pending` в `accepted` или `rejected`. У принятого отклика этапы дают 10/20/30 баллов. Повтор этапа возвращает `409`; уникальные ограничения БД защищают и от одновременных запросов. Сумма команды — исходные баллы sample_data плюс подтверждённые этапы всех её откликов.

## Помощник

Работает серверный деморежим без внешнего ИИ и API-ключей. Он задаёт фиксированные уточняющие вопросы и переносит введённые ответы в карточку. Недостающие факты не генерируются. Настоящий AI-провайдер пока не подключён; его можно добавить в `app/assistant.py`, сохранив контракт из `prompts/`.

## Проверки

```sh
make test
make check
make test-client
make openapi
```

`test` проверяет API, миграции, сохранение данных, валидацию, повторные отклики и одновременное начисление баллов на временных базах. `test-client` требует Node.js 20+ и проверяет fetch-клиент без установки npm-пакетов. Node.js не нужен для запуска сайта. `openapi` создаёт `backend/openapi.json` для передачи контракта фронтенд-разработчику.
