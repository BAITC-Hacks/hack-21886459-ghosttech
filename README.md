# GhostTech

GhostTech помогает бизнесу превращать неформулированную проблему в понятную задачу для команды. Платформа задаёт уточняющие вопросы, собирает карточку задачи, оценивает её готовность и показывает каталог командных откликов.

## Текущий статус

Сейчас проект работает как front-end прототип с синтетическими mock-данными. Основной пользовательский сценарий доступен без API-ключей и backend-интеграции.

## Архитектура

- `frontend/index.html` — оболочка интерфейса и вкладки бизнес-сценария.
- `frontend/app.js` — пошаговый мастер, каталог, отклики и обновление состояния UI.
- `frontend/mock.js` — mock API, рейтинг карточек, задачи, команды и отклики.
- `frontend/api.js` — переключатель режима mock/AI и заготовка API-контракта.
- `backend/` — FastAPI-заготовка для будущей серверной интеграции.
- `sample_data/` и `prompts/` — исходные примеры данных и prompt-контракты.

## Технологии

- HTML, CSS и vanilla JavaScript без frontend-сборщика.
- Python 3.13+, FastAPI и Uvicorn для backend-заготовки.
- `uv` для управления Python-зависимостями.
- Python `http.server` для локального просмотра фронтенда.

## Установка

Для backend-окружения нужен Python 3.13+ и `uv`:

```bash
python3 -m pip install --user uv
make setup
```

Backend-зависимости устанавливаются из `backend/pyproject.toml` по lock-файлу.

## Запуск фронтенда

Из корня проекта:

```bash
python3 -m http.server 5500 --directory .
```

Откройте [http://localhost:5500/frontend/](http://localhost:5500/frontend/).

## Запуск backend-заготовки

```bash
make dev
```

Сервис запускается на `http://127.0.0.1:8000`. Backend пока не подключён к интерфейсу: front-end использует `window.mockApi`.

## Проверка основного сценария

1. Откройте вкладку «Бизнес: новая задача».
2. Нажмите «Подставить пример» и затем «Проанализировать».
3. Ответьте на уточняющие вопросы или сразу нажмите «Собрать карточку».
4. На шаге «Карточка» измените поля и проверьте обновление рейтинга.
5. Перейдите во вкладку «Каталог», примените фильтры темы и уровня.
6. Нажмите «Смотреть отклики» у любой задачи.
7. Во вкладке «Бизнес: отклики» примите или отклоните pending-отклик.

## Формула рейтинга

Рейтинг считается по девяти полям карточки и ограничен значением 100:

- контекст — 10;
- потребность — 10;
- данные — 20;
- ожидаемый результат — 15;
- критерии успеха — 15;
- ограничения — 10;
- пользователи — 10;
- контакт — 5;
- формат взаимодействия — 5.

Уровни:

- `0–39` — «Черновик»;
- `40–69` — «Рабочая»;
- `70–89` — «Готовая»;
- `90–100` — «Приоритетная».

Для поля «Критерии успеха» полный балл начисляется при наличии измеримой метрики или процента.

## Каталог и отклики

Каталог сортирует задачи по рейтингу и поддерживает фильтрацию по теме и уровню. Для каждой задачи отображаются потребность, рейтинг и количество откликов.

Бизнес может просматривать предложение команды и менять его статус с `pending` на `accepted` или `rejected`. В mock API также подготовлены методы подтверждения этапов `prototype`, `testing` и `final`.

## Использование ИИ

В демо-режиме вопросы и сборка карточки выполняются mock API. Контракты будущих AI-вызовов находятся в `prompts/analyze.md` и `prompts/build_card.md`, а настройки полей — в `prompts/field_hints.json`.

## Безопасность и ограничения

- В репозитории используются только синтетические примеры.
- Не добавляйте реальные персональные данные, токены и ключи в mock-файлы.
- Данные mock API хранятся только в памяти страницы и сбрасываются после перезагрузки.
- Реальный backend, авторизация, постоянное хранение и деплой пока не подключены.

## Проверки

```bash
make test
make check
```

Эти команды проверяют backend-тесты и стиль Python-кода. Для front-end прототипа основной smoke-тест выполняется по сценарию выше в браузере.
