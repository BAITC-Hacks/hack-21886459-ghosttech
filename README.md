# GhostTech

Платформа для подготовки бизнес-задач, оценки их готовности и работы с откликами команд.
**Backend:** Python + FastAPI + SQLAlchemy + SQLite. **Frontend:** HTML + CSS + JavaScript без сборки.

Текущая версия предназначена для локальной демонстрации. Просмотр опубликованных задач и демо-данных доступен без входа; создание и изменение требуют аккаунта с ролью «Бизнес» или «Студент». Сервер разработки слушает `127.0.0.1`. Проверки безопасности не означают готовности к публичному размещению.

## Быстрый запуск

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/). Из корня репозитория:

```sh
make setup
make seed
make dev
```

- Сайт: http://127.0.0.1:8000/
- Swagger: http://127.0.0.1:8000/docs
- OpenAPI: http://127.0.0.1:8000/openapi.json
- Проверка сервера: http://127.0.0.1:8000/api/health

`make setup` устанавливает зависимости из `backend/uv.lock`, создаёт `backend/.venv`, копирует `.env.example`, если `.env` отсутствует, и применяет миграции. `make seed` загружает примеры без дубликатов и без перезаписи ваших изменений. Остановка сервера: Ctrl+C.

Без `make`:

```sh
uv sync --project backend --locked
uv run --directory backend --locked python -m app.cli setup
uv run --directory backend --locked python -m app.cli seed
uv run --project backend --locked uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Для входа через cookie открывайте страницу с того же адреса и порта FastAPI, например `http://127.0.0.1:8000/` или `http://127.0.0.1:8001/`, если сервер запущен на порту 8001.

Фронтенд также можно запустить на отдельном сервере:

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory frontend
```

При раздаче с `8080` клиент автоматически обращается к FastAPI на `8000` с тем же именем хоста и передаёт cookie через `credentials: 'include'`; эти адреса по умолчанию перечислены в `FRONTEND_ORIGINS`. Для другого адреса задайте `window.API_BASE_URL` до подключения `api.js` и разрешите origin страницы через `FRONTEND_ORIGINS`. `localhost` и `127.0.0.1` для cookie не взаимозаменяемы. При раздаче через FastAPI клиент использует относительный `/api`.

## База данных и миграции

По умолчанию база — `backend/data/app.sqlite3`. Относительные SQLite-пути в `DATABASE_URL` считаются от `backend/`, поэтому запуск из другого каталога не создаёт случайную вторую базу.

`backend/.env` читается автоматически. Переменные окружения имеют приоритет:

```dotenv
DATABASE_URL=
FRONTEND_ORIGINS=["http://127.0.0.1:8080","http://localhost:8080"]
AI_DAILY_LIMIT=20
```

После изменения моделей создайте и проверьте миграцию:

```sh
uv run --directory backend --locked alembic revision --autogenerate -m "describe schema change"
make migrate
uv run --directory backend --locked alembic check
```

Перед обновлением рабочей базы сохраните её копию. Приложение не изменяет схему автоматически при старте. Историческая миграция `0001` содержала аккаунты; `0002` удаляла старую модель аккаунтов и связи владельцев, сохраняя задачи, команды и отклики. Новая модель аккаунтов и сессий добавлена отдельной миграцией. Обратное восстановление данных, удалённых миграцией `0002`, возможно из резервной копии; её автоматический downgrade не предусмотрен. Таблица старых демо-заметок сохраняется, но `/api/notes` больше не используется.

Для PostgreSQL предусмотрен драйвер:

```sh
uv sync --project backend --extra postgres --locked
```

```dotenv
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/ghosttech
```

Затем примените миграции к созданной PostgreSQL-базе. Перенос существующих данных из SQLite выполняется отдельно; в этой работе тестировалась SQLite.

## Основной сценарий

1. Зарегистрируйте аккаунт «Бизнес» и войдите. В мастере нажмите «Подставить пример», затем «Проанализировать».
2. Ответьте на вопросы и нажмите «Собрать карточку».
3. Заполните поля. Рейтинг и подсказки рассчитывает API.
4. Перейдите к публикации, подтвердите сведения и опубликуйте задачу.
5. Выйдите и зарегистрируйте отдельный аккаунт «Студент». Создайте свою команду, найдите задачу в каталоге и отправьте отклик с идеей, планом, сроком и ссылкой на прототип.
6. Снова войдите в аккаунт «Бизнес». В разделе «Бизнес: отклики» выберите свою задачу и примите отклик.
7. Подтвердите этапы: прототип, тестирование, финал. Баллы начисляются по одному разу.
8. Перезапустите сервер — опубликованная задача, решение и баллы сохранятся.

Разделы интерфейса зависят от роли вошедшего аккаунта: бизнесу доступны новая задача и отклики на свои задачи, студенту — каталог и его команда. Переключение вкладок не меняет роль на сервере. Если своей команды ещё нет, форму её создания можно открыть при отклике из каталога. Кнопка «Редактировать карточку» в разделе откликов открывает собственную сохранённую задачу в мастере.

Во вкладке «Команда» доступны профиль, рекомендации с объяснением совпадений по интересам,
навыкам и технологиям, а также отправленные отклики с текущим решением бизнеса.
Рекомендации включают задачи от 40 баллов; они не ограничивают общий каталог.
Кнопка «Откликнуться» в каталоге открывает карточку в кабинете команды — даже для задач
с низким рейтингом. Форма проверяет идею и план (от 20 символов), дату и ссылку на прототип.
Повторный отклик той же команды запрещён сервером. Рекомендации рассчитываются локально
по открытым данным; автоматического назначения команды нет.

Мастер последовательно открывает шаги после анализа и сборки карточки. Изменение карточки
снимает подтверждение публикации. Интерфейс использует FastAPI во всех разделах, включая
рекомендации и отклики; `mock.js` сохранён как исторический демо-источник и не подключается.

## API

Полный контракт, примеры типов и схемы доступны в `/docs`. Также см. [backend/API.md](backend/API.md).

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/health` | Проверка соединения с БД |
| POST | `/api/tasks/analyze` | Уточняющие вопросы |
| POST | `/api/tasks/build-card` | Карточка из черновика и ответов |
| POST | `/api/tasks/score` | Рейтинг, расшифровка и подсказки |
| GET | `/api/tasks` | Опубликованные задачи; фильтры, сортировка, пагинация |
| GET | `/api/tasks/{id}` | Карточка с откликами |
| POST | `/api/tasks` | Создать задачу или неопубликованную карточку |
| PATCH | `/api/tasks/{id}` | Обновить карточку или подтверждение публикации |
| GET / POST | `/api/teams` | Список / создание команды |
| PATCH | `/api/teams/{id}` | Изменить команду |
| GET / POST | `/api/tasks/{id}/proposals` | Список / создание отклика |
| GET | `/api/proposals?team_id={id}` | Отклики выбранной команды с пагинацией |
| PATCH | `/api/proposals/{id}/decision` | Принять или отклонить |
| POST | `/api/proposals/{id}/progress` | Подтвердить этап |

## Рейтинг и правила

Максимальные баллы: контекст 10, потребность 10, данные 20, результат 15, критерии успеха 15, ограничения 10, участники 10, контакт 5, формат взаимодействия 5.

Уровни: `draft` — 0–39, `working` — 40–69, `ready` — 70–89, `priority` — 90–100. Формула полноты перенесена из исходного `mock.js`; подсказки учитывают также частично заполненные поля. При загрузке sample_data рейтинг пересчитывается из карточек — исторические числа в JSON могут отличаться от результата формулы.

Рейтинг всегда считает сервер. Неопубликованные карточки исключены из каталога; `include_drafts=true` добавляет только черновики вошедшего владельца. Прямое чтение чужого черновика закрыто. `confirmed` — факт публикации, `level` — качество заполнения, это независимые признаки.

Одна команда может отправить один отклик на задачу. Решение меняется только из `pending` в `accepted` или `rejected`. У принятого отклика этапы дают 10/20/30 баллов. Повтор этапа возвращает `409`; уникальные ограничения БД защищают и от одновременных запросов. Сумма команды — исходные баллы sample_data плюс подтверждённые этапы всех её откликов.

## Помощник

При запуске через `make dev` обработчики в `backend/app/main.py` используют
`backend/ai.py`: анализ черновика возвращает 3–5 вопросов, сборка — редактируемую
карточку. OpenAI вызывается через Chat Completions с JSON-ответом; проверка схем
находится в `backend/schemas_ai.py`, локальный деморежим — в `backend/ai_demo.py`.
Прежняя реализация Agents SDK в `backend/app/ai_agents.py` сохранена, но эти три
маршрута (`health`, `analyze`, `build-card`) обслуживает новый модуль.

Установите зависимости через `make setup`. Настройки находятся в **backend/.env**:

```dotenv
AI_MODE=auto
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-mini
AI_TIMEOUT_SECONDS=20
AI_DAILY_LIMIT=20
```

- `auto`: с непустым ключом используется OpenAI, без ключа — деморежим.
- `demo`: локальная обработка без внешних запросов.
- Значение `openai` совместимо с `auto`; отсутствие ключа также включает деморежим.

После изменения настроек перезапустите сервер. `.env` исключён из Git.
Анализ и сборка карточки доступны вошедшему бизнес-профилю. На один аккаунт действует лимит 20 обращений в сутки по UTC, включая деморежим; `AI_DAILY_LIMIT` меняет его значение. После исчерпания лимита сервер возвращает `429`. Оценка готовности карточки (`/api/tasks/score`) не расходует этот лимит.
`GET /api/health` возвращает `{status, mode}`, где `mode` — `ai` или `demo`.
Это отражает конфигурацию, а не проверку доступности провайдера.

Черновик содержит 10–3000 символов, тема — 1–60; каждый ответ — до 1000 символов,
максимум 10 ответов. Пустые ответы пропускаются. Ошибка входных данных возвращает
`422` с `{error: {code: "validation_error", message: "…"}}`.

Промпты читаются из `prompts/`. При некорректном ответе модели выполняется одна
повторная попытка с указанием исправить JSON. При ошибке провайдера, отсутствии
промпта или повторно некорректном ответе используется деморежим. В результате
сборки при таком переходе есть предупреждение. Проверка карточки отмечает
потенциально выдуманные числа, контакты и ссылки, но не гарантирует истинность
текста: пользователь проверяет, редактирует и подтверждает карточку перед
публикацией. Рейтинг и решение по откликам остаются отдельными действиями.

Для проверки выберите профиль «Бизнес», подставьте пример, выполните анализ,
ответьте на вопросы и соберите карточку. Автотесты проверяют валидацию, повторную
попытку, деморежим и контракт SDK без внешних API-вызовов и оплачиваемых запросов.

## Проверки

```sh
make test
make check
make test-client
make security-check
make openapi
```

`test` проверяет API, миграции, сохранение данных, валидацию, повторные отклики и одновременное начисление баллов на временных базах. `test-client` требует Node.js 20+ и проверяет fetch-клиент без установки npm-пакетов. Node.js не нужен для запуска сайта. `security-check` запускает 18 изолированных проверок на временной базе; подробности — в [backend/SECURITY_TESTING.md](backend/SECURITY_TESTING.md). `openapi` создаёт `backend/openapi.json` для передачи контракта фронтенд-разработчику.


## Большой демонстрационный набор

После обновления выполните `make migrate`, затем `make seed`. Загрузка добавляет
20 вымышленных предпринимателей, 80 студентов в 20 новых командах, 80 задач,
200 откликов и 104 подтверждённых этапа. Пять прежних задач и команд и семь
прежних откликов сохраняются. На чистой базе получается 85 задач, 25 команд,
100 участников и 207 откликов.

Новые задачи распределены поровну по восьми темам: образование, ритейл, общепит,
логистика, производство, туризм, услуги и экология. Рейтинг готовности считается
обычной формулой; баллы команд начисляются за подтверждённые этапы. Даты новых
демо-записей привязаны к дню первой загрузки. Повторный запуск не перезаписывает
карточки, профили, решения и прогресс и не создаёт дубликаты.

- В профиле «Студент» во вкладке «Команда» видны состав, навыки и отклики выбранной команды.
- Демо-предприниматели и их задачи доступны для просмотра; новая задача создаётся от имени вошедшего бизнес-аккаунта.
- Каталог поддерживает темы со счётчиками, заказчика и поиск по названию/потребности.
- В разделе «Бизнес: отклики» предприниматель может принять отклик на свою задачу
  или подтвердить следующий этап работы. Изменения сохраняются в базе.

Демо-профили явно помечены и доступны только для просмотра. Они не являются аккаунтами для входа; чужие демо-задачи и команды нельзя редактировать или использовать как свои. Для действий нужны собственные аккаунты «Бизнес» и «Студент». Контакты и ссылки используют `example.com`; ссылки на прототипы служат примерами.


В каталоге кнопка «Фильтры и сортировка» открывает настройки темы, готовности,
заказчика, типа работы и наличия откликов. Доступны сортировки по рейтингу,
дате и количеству откликов. Настройки применяются сразу; «Сбросить настройки»
очищает фильтры и поиск и возвращает сортировку по высокому рейтингу. При
нажатии «Показать ещё» выбранные условия сохраняются.

### Анализ описания заказчика и реальные вопросы ИИ

Для демонстрации с OpenAI в `backend/.env` задайте `AI_MODE=auto` и
`OPENAI_API_KEY`. Запускайте сервер без переопределения `AI_MODE=demo`.
Принудительный `demo` использует шаблонные вопросы даже при наличии ключа.
Ключ хранится только на сервере и не коммитится.

Анализ возвращает 3–5 вопросов по содержанию конкретного запроса, краткое
объяснение `summary`, предварительную карточку `draft_card`, перечни заполненных
и отсутствующих полей, `warnings` и фактический `mode`. Оценка `score` вычисляется
на сервере существующей формулой, а не моделью. При анализе в баллы идут только
поля, извлечённые из самого черновика: неподтверждённые фрагменты исключаются.
На шаге уточнения видны анализ полноты и расшифровка баллов. После ответов и
редактирования показано изменение рейтинга относительно черновика.

При сборке можно передать исходный текст вопроса в необязательном
`answers[].question`, чтобы ИИ понимал короткие ответы. Вопросы и предложенные
примеры сами по себе не считаются фактами. Карточка остаётся редактируемой;
публикацию и выбор команды подтверждает человек.

Индикатор вверху различает «ИИ включён», фактически полученный «Ответ OpenAI»
и деморежим. При сбое API показано предупреждение о fallback. `/api/health`
сообщает конфигурацию; успешную генерацию подтверждает `mode: "ai"` в ответе
`/api/tasks/analyze` или `/api/tasks/build-card`.

Проверка содержания: сравните черновик про списания в пекарне с черновиком про
маршруты курьеров. Вопросы должны упоминать соответствующие процессы и не
запрашивать повторно уже указанный срок или контакт. На слабом описании после
конкретных ответов рейтинг должен вырасти. Правило начисления баллов описано
в разделе рейтинга; предварительная оценка до публикации требует проверки.

## Лидеры и публичные профили

Раздел «Лидеры» доступен бизнесу и студентам. Переключатель показывает топ-10
бизнесов и команд за текущий календарный месяц (UTC) либо за всё время.

- Бизнес: сумма текущего рейтинга опубликованных задач, **созданных** за период,
  плюс баллы подтверждённых этапов за период по его опубликованным задачам.
- Команда: баллы подтверждённых этапов по опубликованным задачам за период;
  стартовые баллы команды добавляются только в режиме «Всё время».
- Время этапа определяется `Progress.created_at`, время задачи — `Task.created_at`.
  При равных баллах сначала сравниваются завершённые задачи, затем ID профиля.
  Неопубликованные задачи, неподтверждённые этапы и будущие события исключены.
- «Открытые задачи» — опубликованные задачи без принятого отклика; это показатель
  текущего состояния, независимо от периода рейтинга. Профили неактивных за месяц
  участников могут отсутствовать в месячном топе. Демо-профили подписаны «Демо».

В профиле бизнеса видны публичные задачи и контакты из них. В профиле команды —
состав, навыки, принятые проекты и контакт для связи. Просмотр доступен из обеих
ролей; из задачи студент может перейти к существующей форме отклика.
Контакт команды редактируется в кабинете команды кнопкой «Контакты и профиль
команды». Email и HTTP(S)-ссылки открываются пользователем; остальные контакты
показаны как текст. Встроенной переписки и автоматической отправки сообщений нет.

После обновления выполните `make setup` (миграция `0004` добавляет необязательное
поле контакта, сохраняя команды и баллы). На старой базе контакты пустые.
Для демонстрационных задач и профилей выполните `make seed`.

API:

- `GET /api/leaderboard?period=month|all&limit=10` — рейтинг и границы периода.
- `GET /api/profiles/businesses/{id}?offset=0&limit=12` — профиль и задачи бизнеса.
- `GET /api/profiles/teams/{id}?offset=0&limit=12` — профиль и проекты команды.
- `POST /api/teams`, `PATCH /api/teams/{id}` принимают необязательный `contact`
  до 500 символов. Старые клиенты, не передающие это поле при изменении команды,
  сохраняют его прежнее значение.
