# Контракт API

Базовый URL: `http://127.0.0.1:8000/api` (или тот же путь на другом порту FastAPI, например `8001`). Все ID — строки. Опубликованный каталог и демо-данные можно читать без входа; изменение данных требует cookie-сессии с подходящей ролью.

## Аккаунты и доступ

- `POST /auth/register` — регистрация: `{"email":"user@example.com","password":"не менее 8 символов","name":"Имя","role":"business"}`. Роль — `business` или `student`; ответ `201` содержит профиль и устанавливает cookie `ghosttech_session`.
- `POST /auth/login` — вход: `{"email":"user@example.com","password":"..."}`. Ответ содержит профиль и устанавливает cookie-сессию.
- `GET /auth/me` — профиль текущего аккаунта; без входа `401`.
- `POST /auth/logout` — выход без тела запроса, ответ `204`; сервер отзывает сессию и удаляет cookie.

Сессия хранится на сервере и передаётся браузером через `HttpOnly` cookie с `SameSite=Lax`; время жизни — семь дней, при HTTPS добавляется флаг `Secure`. Роль выбирается при регистрации и проверяется сервером. Бизнес создаёт и изменяет только свои задачи, принимает отклики и подтверждает этапы на них. Студент создаёт свою команду, редактирует только её и отправляет отклик только от неё. Демо-профили, команды и задачи предназначены для публичного просмотра; работать от их имени нельзя.

Операции POST/PATCH/PUT требуют JSON с `Content-Type: application/json`; исключение — `/auth/logout` без тела. Middleware отклоняет изменяющий `/api/` запрос с посторонним `Origin` (`403`) и запрос к JSON-операции с другим `Content-Type` (`415`). Разрешены origin самого FastAPI-сервера и адреса из `FRONTEND_ORIGINS`. Эти проверки дополняют серверную авторизацию; обычный запрос без `Origin` также должен проходить проверку cookie и роли.

Ошибки обычно имеют вид `{"detail":"сообщение"}`; ошибки Pydantic (`422`) содержат массив `detail` с `loc`, `msg`, `type`. Для защищённых операций возможны `401` без входа и `403` при чужой роли или объекте.

## Карточка и рейтинг

Поля `card`: `title`, `topic`, `context`, `need`, `users`, `data`, `constraints`, `expected_result`, `success_criteria`, `contact`, `interaction_format`. Все — строки, отсутствующие поля становятся пустыми. Название ограничено 200 символами, тема — 100, контакт — 500, прочие поля — 5000.

`POST /tasks/analyze`:

```json
{"draft_text":"Нужен учёт посещаемости кружков","topic":"образование"}
```

Ответ: `questions: [{id, field, question}]`, `filled_fields`, `missing_fields`, `mode: "demo" | "openai"`. Вопросов от 3 до 5, идентификаторы и поля уникальны.
Для анализа и сборки карточки нужен бизнес-аккаунт. Общий лимит этих двух операций — 20 обращений на аккаунт в сутки по UTC; параметр `AI_DAILY_LIMIT` меняет число. После исчерпания возвращается `429`. Вызов засчитывается до обращения к провайдеру, в том числе в деморежиме.

`POST /tasks/build-card`:

```json
{"draft_text":"Нужен учёт посещаемости","topic":"образование","answers":[{"question_id":"q1","field":"data","answer":"Есть журнал посещений"}]}
```

Ответ: `card`, массив строк `warnings` и `mode: "demo" | "openai"`. Поле `field` ограничено ключами карточки, повторные ответы для одного поля запрещены.

`POST /tasks/score`: `{"card": {...}}`. Ответ: `score`, `level`, `breakdown: [{field,label,max,earned,reason}]`, `missing: [{field,hint,potential_points}]`.

В приложении `app.main:app` анализ и сборка используют `backend/ai.py`.
Черновик: 10–3000 символов; обязательная тема: 1–60; до 10 ответов по 1000 символов.
Ошибки входных данных этих двух методов возвращают `422` с
`{"error":{"code":"validation_error","message":"сообщение"}}`.
При сбое провайдера или повторно некорректном ответе используется деморежим;
сборка добавляет предупреждение. Остальные методы сохраняют формат ошибок `detail`.

`GET /health`: `{status, mode}`, где `mode` — `ai` или `demo`. Режим отражает
конфигурацию; это не проверка связи с OpenAI. Прежние схемы помощника из
`app.api.create_app` относятся к сохранённой реализации Agents SDK.

## Задачи

`POST /tasks`:

```json
{"card":{"title":"Учёт посещаемости","topic":"образование","need":"Быстро видеть пропуски занятий"},"confirmed":true}
```

Доступен бизнес-аккаунту. Автор задачи берётся из его сессии; необязательный `owner_id`, если передан, должен совпадать с ID этого аккаунта. Возвращает `201`: `{id, card, confirmed, score, level, breakdown, missing, created_at, updated_at, proposals}`.
Для публикации обязательны непустые `title` и `topic`. При `confirmed: false` можно сохранять незаполненную карточку.

`GET /tasks?topic=образование&level=ready&offset=0&limit=50` возвращает **массив** сводок:
`{id, title, topic, need, confirmed, score, level, proposals_count, created_at}`.
`limit` от 1 до 100. Пустые фильтры следует опускать. Сортировка: рейтинг по убыванию, дата по убыванию, ID. `include_drafts=true` добавляет только черновики вошедшего владельца; чужие черновики не выдаются.

`GET /tasks/{id}` возвращает полную опубликованную карточку или собственный черновик с доступными этому пользователю откликами. Чужой черновик возвращает `404`.

`PATCH /tasks/{id}` доступен только бизнесу-владельцу недемонстрационной задачи и принимает `card` и/или `confirmed`. Переданное `card` **заменяет все поля карточки**, а не выполняет вложенный частичный merge. Не передавайте вычисляемые `score` и `level`. Изменение карточки снимает подтверждение, если в том же запросе не передано `confirmed: true`.

## Команды

`GET /teams?offset=0&limit=50` — массив `{id, name, interests, skills, tech, points}`.

`POST /teams` и `PATCH /teams/{id}`:

```json
{"name":"GhostTech","interests":["образование"],"skills":["аналитика"],"tech":["Python"]}
```

Создание доступно вошедшему студенту, ещё не состоящему в команде; новая команда закрепляется за ним. При PATCH студент передаёт полную редактируемую форму только своей недемонстрационной команды. `points` вычисляется сервером и не принимается в запросе.

## Отклики и прогресс

`POST /tasks/{id}/proposals`:

```json
{"team_id":"team1","idea":"Сделать журнал посещений","plan":"Прототип, проверка, запуск","deadline":"2027-01-10","prototype_url":"https://example.com/prototype"}
```

Отклик создаёт вошедший студент только от своей недемонстрационной команды на опубликованную недемонстрационную задачу. Ссылка необязательна; допускается только HTTP/HTTPS. Ответ `201`:
`{id, task_id, team_id, idea, plan, deadline, prototype_url, status, stages_done, created_at}`.
`GET /tasks/{id}/proposals` возвращает доступные этому пользователю отклики; чужие приватные отклики не раскрываются.

`GET /proposals?team_id={id}&offset=0&limit=100` возвращает только публичные демо-отклики и отклики, доступные вошедшему владельцу задачи или своей команде. `team_id` сужает эту выборку, а без него возвращается вся доступная выборка. `limit` от 1 до 100; неизвестная команда — `404`. Статус и подтверждённые этапы берутся из базы данных.

`PATCH /proposals/{id}/decision`: `{"decision":"accepted"}` или `{"decision":"rejected"}`. Решает только бизнес-владелец задачи; повторное решение — `409`.

`POST /proposals/{id}/progress`: `{"stage":"prototype"}` / `testing` / `final`.
Ответ `201`: `{proposal_id, team_id, stages_done, points_total, team_points_total}`.
`points_total` — баллы этого отклика, `team_points_total` — вся сумма команды. Подтвердить этап принятого отклика может только бизнес-владелец задачи. Порядок подтверждения этапов не ограничен; каждый учитывается единожды.

## Подключение фронтенда

Готовый клиент — `frontend/api.js`: методы возвращают Promise, вызывайте их с `await` и обрабатывайте исключения. HTTP-статус доступен как `error.status`. Работающий интерфейс использует API; `mock.js` больше не подключён.

Для cookie-входа рекомендуется открыть сайт на том же origin, что и FastAPI, например `http://127.0.0.1:8001/`. Тогда клиент использует относительный `/api` и браузер передаёт cookie автоматически. Отдельный фронтенд на `8080` автоматически обращается к FastAPI на `8000` с тем же именем хоста; fetch-клиент использует `credentials: 'include'`, а адреса `8080` по умолчанию разрешены в `FRONTEND_ORIGINS`. Для другого адреса задайте `window.API_BASE_URL` и добавьте origin страницы в `FRONTEND_ORIGINS`. `localhost` и `127.0.0.1` используют разные cookie.


## Демонстрационные участники и темы

- `GET /participants?role=business|student&team_id=…&offset=0&limit=50` — публичные
  профили; роль и команда необязательны, максимальный размер страницы 100.
- `GET /topics` — темы опубликованных задач с `tasks_count`.
- `GET /tasks` дополнительно принимает `owner_id` и `search` (название и потребность).
- Ответы задач дополнены `owner`, `is_demo` и `work_tags`; команды — `members` и `is_demo`.
- `POST /tasks` может принять `owner_id` только с ID вошедшего бизнес-аккаунта; при его отсутствии автор определяется из сессии. Студент не может создать бизнес-задачу.
- Редактирование карточки не меняет автора. Демонстрационные профили — данные для просмотра, зарегистрированные профили привязаны к аккаунтам.


### Фильтрация и порядок каталога

`GET /api/tasks` поддерживает дополнительные параметры:

- `work_type` — точное совпадение с тегом типа работы (например, `аналитика`).
- `proposals=any|none|has` — любые задачи, без откликов или с откликами.
- `sort=score_desc|score_asc|newest|oldest|proposals_desc` — рейтинг по убыванию
  (по умолчанию), рейтинг по возрастанию, новые, старые или больше откликов.

Эти параметры сочетаются с темой, уровнем, заказчиком и поиском. Фильтрация и
сортировка выполняются до `offset`/`limit`; ID обеспечивает стабильный порядок
при равных значениях. Формат ответа остаётся списком задач.
